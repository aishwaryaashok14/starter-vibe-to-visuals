# Store Kit schema and validation

Create one file named `STORE-KIT.md`. If file writing is unavailable, return one clearly labelled copyable block.

Use the structure in `templates/STORE-KIT-TEMPLATE.md` when it is available. The completed file must contain these sections:

1. Store promise.
2. Customer and moment.
3. Commercial position.
4. Chosen direction with a short rationale.
5. Product collection as a table containing exactly three products.
6. Visual rules.
7. Voice and campaign copy.
8. Non-negotiables.
9. Avoid list.

## Product table

Every product needs an ID, name, factual description, price, material, colour, silhouette, crop hint, zoom value, and approved factual claims. Use `product-family.png` as the shared image reference unless the project already uses another supplied path.

The three products must remain distinguishable in a single family image. Change silhouette, scale, material detail, or colour when two products could be confused.

## Campaign copy

Include an approved hero headline, supporting line, social line, and three video beats. Video beat 2 must use an exact product name and price. Keep the copy consistent with the store promise.

## Validation

Before completion, report pass or repair for:

- one clear store promise;
- exactly three physical products;
- complete product fields;
- one currency and coherent prices;
- no unsupported claims;
- five named palette colours with valid hex values;
- observable rules for type, light, composition, materials, and motion;
- approved copy for the website, social image, and three video beats;
- at least four concrete items to avoid;
- one written source file only.
